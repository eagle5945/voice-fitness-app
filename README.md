# 음성 운동 기록

## 개인 배포 설정

서버 주소, SSH 사용자·키 파일 경로, NAS 설치 경로, 공개 접속 주소와 백업 위치는 루트 `.env`에서만 관리합니다. 새 환경에서는 `Copy-Item .env.example .env`로 예시를 복사한 후 값을 입력합니다. 기존 `.env`가 있으면 덮어쓰지 마세요. `.env`와 `.env.*`는 Git에서 제외하고 가짜 값만 담은 `.env.example`만 공유합니다.

현재 `.env`는 수동 배포 시 참조하는 로컬 설정표입니다. PWA, Docker Compose, 패키지 생성기는 이 파일을 자동으로 읽지 않습니다. PWA는 상대 주소와 기기 저장소를 사용하므로 서버 주소를 JavaScript에 넣을 필요가 없습니다. `pwa/`나 NAS의 `site/`에 `.env`를 복사하지 마세요. 브라우저에 전달한 값은 비밀로 유지할 수 없습니다. SSH 개인키 내용·비밀번호는 이 파일에 넣지 않고 기존 SSH 키 저장소에서 관리합니다.

패키지 생성기는 명시된 정적 파일·배포 설정만 포함합니다. `.env`, 개인 기록, 인증파일은 패키지와 GitHub 업로드 대상에서 제외합니다. 루프백 주소(`127.0.0.1`)와 테스트용 도메인은 개인 서버 정보가 아니므로 코드에 유지합니다. 이미 공개한 이전 커밋의 정보는 `.gitignore`나 새 커밋으로 지워지지 않습니다.

현재 방식은 **iPhone 기본 키보드 받아쓰기 + PWA**입니다. 앱의 ‘받아쓰기로 입력’을 누르고 키보드 마이크로 말한 뒤, 문장을 확인·수정하고 ‘입력 확인 → 기록 저장’을 누릅니다. 앱은 음성을 녹음하거나 STT 서버를 호출하지 않습니다. iOS 받아쓰기의 처리 방식과 사용 가능 여부는 기기 설정에 따릅니다.

‘70킬로 20회’, ‘칠십 키로 스무 회’, ‘20회’를 지원합니다. 횟수만 입력하면 현재 종목의 설정 중량을 사용합니다. 불명확한 문장은 자동 저장하지 않습니다. 미리보기 이후 문장을 수정하면 다시 확인해야 합니다.

## 실행 및 검증

```powershell
python -m http.server 8765 --bind 127.0.0.1
node --test pwa/*.test.mjs
python scripts/build_nas_package.py
```

로컬 주소: http://127.0.0.1:8765/pwa/. 키보드 받아쓰기는 실제 iPhone에서 확인합니다. 데스크톱에서는 문장 입력·해석·저장·수정·기록 조회를 확인할 수 있습니다.

기록은 기존 IndexedDB에 저장하며 데이터 형식과 공개 주소는 유지합니다. Safari 사이트 데이터를 지우지 마세요. 기록 화면에서 JSON 파일로 백업할 수 있습니다.

[NAS 배포 안내](deploy/nas/README.md). 신규 패키지는 정적 웹 서버만 사용하고 Hermes 인증정보가 필요 없습니다. 기존 backend STT 코드와 관련 설계 문서는 이전 구현 참고용으로 보존하며 현재 PWA에서는 사용하지 않습니다.

## CSV 내보내기

기록 → 기록 보관 → CSV로 내려받기. 전체 기록의 유효 세트를 한 행씩 내보내며 취소 세트는 제외합니다. 운동 시작·기록 시각은 한국시간, 중량은 kg입니다. UTF-8 BOM과 CSV 이스케이프를 적용합니다. CSV는 조회용으로 복원 기능을 제공하지 않으며, 기존 JSON 백업·복원은 유지합니다. CSV 다운로드는 마지막 JSON 백업 시각을 변경하지 않습니다.

## 저장 루틴

첫 화면의 루틴 관리에서 가슴·등·하체 등 제목을 만들고 운동명, 장비, 중량, 목표 횟수, 세트 수를 저장합니다. 첫 화면에서 오늘 루틴을 선택하면 운동 목록을 미리 보고 시작할 수 있습니다. 진행 화면은 종목 순서와 세트 진행 수를 보여주며 계획한 세트를 채우면 다음 종목 버튼이 나타납니다. 루틴은 iPhone IndexedDB 및 JSON 백업에 보관됩니다. CSV에는 완료 운동 내 실제 세트 기록을 내보냅니다.

## 20260926-12 사용 흐름 개선

오늘·루틴·기록의 하단 메뉴로 이동합니다. 오늘 화면은 루틴을 바로 선택하고 운동을 시작하거나 진행 중인 운동을 이어갑니다. 운동 중에는 현재 중량·목표 횟수와 받아쓰기/직접 입력 버튼을 먼저 보여주고, 전체 종목 순서는 펼쳐볼 수 있습니다. 루틴 편집의 위/아래 버튼으로 입력값을 유지하며 순서를 바꿀 수 있습니다. 목표 세트를 모두 채운 종목은 다음 미완료 종목으로 안내합니다. 백업과 CSV 기능은 기록 화면 아래에서 펼쳐 사용할 수 있습니다.

## 네온 테마 · 20260926-13

블랙 배경, 네온 그린 주요 동작, 블루 보조 동작을 적용했습니다. `neon.css`는 기존 레이아웃 위에 적용되는 테마이며 패키지와 서비스 워커 캐시에 포함됩니다. OS 테마와 관계없이 다크 화면을 사용합니다.

운동 진행 화면의 원형 마이크 버튼은 기존 받아쓰기 입력창을 엽니다. iPhone 키보드 마이크로 입력하며, 앱이 직접 녹음하거나 음성 파형을 생성하지 않습니다. 루틴·세트·기록 저장 형식은 그대로입니다.

검증: PWA 테스트 42개 통과, 로컬 브라우저에서 문장 해석·세트 저장 확인, NAS 정적 파일 백업 및 교체 후 공개 파일 5개 SHA256 일치 확인. iPhone 실기기에서 업데이트 화면과 키보드 받아쓰기는 별도 확인이 필요합니다.

## 운동 기록 삭제 · 20260927-14

기록 탭에서 운동 회차마다 삭제를 선택하거나 회차 상세 화면에서 특정 세트를 삭제할 수 있습니다. 내보내기·복원 영역에는 전체 운동 기록 삭제를 추가했습니다. 삭제 전 확인창을 표시합니다. 전체 초기화는 운동 세션·세트 및 진행 중 운동만 지우고 저장한 루틴은 유지합니다. 개별 회차 삭제 시 진행 중 회차라면 해당 운동도 종료됩니다. 삭제 전에 기록 탭에서 JSON 백업을 저장할 수 있습니다.

## 자동 증량 코치 · 20261001-19

운동 화면에서 같은 이름·장비의 지난 기록이 계획 세트를 모두 목표 횟수 이상 채웠다면 다음 중량을 제안합니다. 루틴이 없는 자유 운동은 기록한 세트 전부가 목표 횟수를 넘어야 합니다. 기준 중량은 종목 설정값이 아니라 실제 기록한 세트 중량입니다. 증량 폭은 바벨 2.5kg, 덤벨 1kg, 머신 5kg이며 `pwa/progression.mjs`의 `PROGRESSION_STEP`에서 바꿉니다.

‘올리기’는 현재 운동의 목표 중량만 바꾸고 저장된 루틴은 바꾸지 않습니다. ‘유지’는 화면을 닫기 전까지만 기억합니다. 첫 세트를 기록하거나 오늘 목표 횟수가 지난번보다 많으면 제안하지 않습니다. 저장 형식은 그대로입니다.

## 신기록 · 추정 1RM · 20261001-20

세트를 새로 저장할 때 추정 1RM(`중량 × (1 + 횟수/30)`, 1회는 중량 그대로, 0.1kg 반올림)이 같은 이름·장비의 이전 최고를 넘으면 저장 안내에 신기록을 함께 표시합니다. 비교 대상은 취소하지 않은 모든 세트이며 오늘 앞서 한 세트도 포함합니다. 그 종목을 처음 하는 운동 회차, 중량 0kg 세트, 세트 수정은 신기록을 알리지 않습니다.

기록 탭 위쪽에 종목별 추정 1RM을 보여줍니다. 최근 운동한 종목 4개를 먼저 보이고 나머지는 펼쳐 봅니다. 회차마다 가장 높은 값을 최근 12회까지 선으로 그립니다. 덤벨은 한 손 중량 기준입니다. 횟수가 많을수록 추정값의 절대 정확도는 떨어지므로 같은 종목의 추이 비교용으로 사용합니다. 저장 형식은 그대로입니다.

## 휴식 타이머 · 20261001-21

운동 화면에 진행 중인 운동의 마지막 세트 이후 경과 시간을 “휴식 1:15 / 평소 2:00”처럼 표시합니다. 경과 시간은 저장된 세트 시각으로 계산하므로 앱을 잠시 나갔다 와도 정확합니다. 평소 휴식은 같은 이름·장비 종목의 세트 간격(15초~10분) 중앙값이며 간격이 2개 이상 쌓이면 표시합니다. 평소 시간에 도달하면 타이머가 강조되고, 15분이 지나면 숨깁니다. iOS PWA의 백그라운드 알림은 신뢰하기 어려워 화면 표시만 제공합니다. 저장 형식은 그대로입니다.

## 원판 계산기 · 20261001-22

바벨 종목의 운동 화면 목표 카드에 “바 20kg + 한쪽 20 · 5 · 1.25”처럼 한쪽에 끼울 원판을 표시합니다. 바벨 중량은 바 포함 총중량이므로 바를 뺀 나머지를 양쪽으로 나눠 무거운 원판부터 채웁니다. 원판으로 맞출 수 없는 무게는 남는 양을 함께 알려줍니다. 바 20kg과 원판 20·15·10·5·2.5·1.25kg은 `pwa/plates.mjs`의 `BAR_WEIGHT`, `PLATES`에서 바꿉니다. 저장 형식은 그대로입니다.
