# 음성 운동 기록 — 개인용 PWA MVP 설계

작성일: 2026-09-25  
상태: v2.0 / Safari 음성인식 경로를 설계한 이전 문서. 현재 PWA 화면의 배경 자료.

**다음 구현의 기준:** [Hermes `small` STT 재설계안](hermes-stt-design.md). 현재 Safari 음성인식 경로는 iPhone에서 반복 `aborted` 오류가 있어 교체 대상으로 결정했다. 아래의 `SpeechRecognition` 설명은 신규 목표 구성이 아니다.

화면 흐름은 [screen-design.md](screen-design.md), 시안은 [screen-prototype.html](screen-prototype.html)을 참고한다.

## 1. 결정과 목표

사용자가 세트가 끝난 뒤 iPhone의 마이크 버튼을 누르고 실제 수행 횟수를 말하면 기록하고, 나중에 날짜와 종목별로 확인한다. 첫 사용자는 현재 운동을 별도로 기록하지 않는다. 첫 버전은 본인 iPhone 17 / iOS 27 한 대에서 사용한다. Mac을 사용할 수 없고 앱스토어 등록·설치를 선호하지 않는다.

**변경된 요구:** 인터넷 없이 음성 입력해야 한다는 이전 조건은 철회했다. 짧은 운동 발화를 외부 음성인식 서버로 전송하는 것을 사용자가 허용했다. 따라서 Safari에서 홈 화면에 추가하는 개인용 PWA를 우선 구현 경로로 정한다.

| 구분 | 현재 설계 |
| --- | --- |
| 배포 | HTTPS 모바일웹 + 홈 화면 추가 PWA. Mac·Xcode·앱스토어 등록 불필요 |
| 음성 | 연결된 상태에서 버튼으로 Safari 음성인식 API를 우선 시험. 상시 듣기 제외 |
| 기록 | 세트와 운동일지는 iPhone의 IndexedDB에 저장하고 앱 안에서 조회·수정 |
| 연결 없음 | 음성 입력 불가를 알리고 직접 입력 제공. 기존 기록 조회도 가능한 범위에서 유지 |
| 백업 | JSON 파일 내보내기·복원. 계정과 자동 동기화는 초기 제외 |
| 검증 상태 | 실제 iPhone의 마이크·PWA 동작·인식률·저장 지속성은 확인 전 |

기존 React Native 코드와 Python 서버는 참고자료이며 현재 HTML 목업은 실제 마이크·PWA 설치·저장소가 연결되지 않은 화면 시안이다.

## 2. MVP 기능 범위

1. 첫 실행: 홈 화면 추가 안내, 인터넷이 음성 입력에 필요하다는 설명, 마이크 권한과 시험 입력.
2. 운동 시작·재개: 종목 선택·직접 등록, 중량·목표 횟수 설정.
3. 세트 입력: “8개” 또는 “75킬로 9회”를 말하면 STT 결과를 검증하고 기록. 모호한 값은 저장 전 확인.
4. 복구: 연결 끊김·인식 실패·권한 거부 시 직접 입력. 저장된 세트는 수정·취소·되돌리기 가능.
5. 추적: 날짜별 운동일지, 종목별 과거 세트, 중량·횟수 확인.
6. 보존: 기록 JSON 내보내기와 복원. 복원 전 파일 형식과 중복·덮어쓰기 동작을 확인.

초기는 한국어·kg·일반 웨이트 세트다. 바벨은 바 포함 총중량, 덤벨은 한 손 중량, 머신은 기구 표시 중량을 기본으로 보여준다. 루틴, 휴식 타이머, 워치, 호출어, AI 코칭, 계정 동기화는 후속 범위다.

## 3. 사용자 화면과 흐름

Safari에서 HTTPS 주소 열기 → 선택적으로 홈 화면에 추가 → 마이크 사용 안내·시험 → 운동 선택 → 중량·목표 설정 → 세트 수행 → 마이크 버튼 → 실제 횟수 발화 → 인식·값 검증 → 저장 완료 확인 → 다음 세트 → 기록 조회.

| 화면 | 핵심 행동 |
| --- | --- |
| 사용 시작 | 홈 화면 추가 안내, 온라인 음성·마이크 권한 설명, 시험 입력 |
| 홈 | 운동 시작·이어하기, 최근 기록 |
| 운동 설정 | 종목, 중량, 목표 횟수, 중량 기준 |
| 운동 진행 | 현재 설정·이전 기록·오늘 세트, 마이크·직접 입력·수정 |
| 기록 | 날짜별·종목별 조회와 파일 내보내기·복원 |

연결이 끊기면 **“인터넷 연결이 없어 음성 입력을 사용할 수 없어요”**와 **“직접 입력”**을 표시한다. 연결이 돌아오면 새 음성 입력을 시작할 수 있다. 녹음 또는 전송 중 오류가 나면 자동으로 세트를 만들지 않는다. 목표 10회로 설정했더라도 “8개”는 실제 8회만 저장한다.

## 4. 음성·데이터 신뢰성 규칙

- “8개”, “여덟 번”, “8회”는 현재 종목·중량의 8회다. “75킬로 9회”는 해당 세트만 75kg 9회로 저장한다.
- “다음은 75로”, 무음, 불명확한 문장은 세트로 저장하지 않는다. 목표 횟수나 첫 숫자로 임의 보정하지 않는다.
- 모호한 값은 사용자가 선택하거나 다시 말하기 전까지 보류한다. 명확한 값은 저장 후 결과와 수정·취소를 바로 보여준다.
- 녹음 시작 당시의 종목·중량 문맥을 사용한다. 늦게 도착한 취소 응답은 무시하고 같은 입력 이벤트 ID의 중복 응답은 한 번만 저장한다.
- 실제 로컬 저장 성공 후에만 “저장됨”을 표시한다. 브라우저 중단·잠금·전화·전송 실패로 끝나지 않은 녹음은 기록으로 만들지 않는다.
- 음성 오디오는 전송 후 서버에서 즉시 폐기하고 기본적으로 서버에 운동일지나 전사 원문을 저장하지 않는 정책을 제안한다. 선택한 STT 제공자의 처리·보존 조건은 도입 전에 확인한다.

데이터는 운동일지(시작·종료 시각, 상태) → 운동 항목(종목·중량·목표) → 세트(ID, 실제 중량·횟수, 중량 기준, 시각, 입력 방식, 입력 이벤트 ID)로 둔다. 목표와 실제 수행값을 분리하고 다른 장비·중량 기준의 기록을 같은 수치로 합치지 않는다.

PWA의 IndexedDB는 기기 상황에 따라 지워질 수 있다. 앱 시작 시 저장 가능 여부를 확인하고 `navigator.storage.persist()` 요청 결과를 확인한다. 기록 화면에서 **내보내기·복원 및 마지막 백업 시점**을 제공한다. PWA 삭제, Safari 사이트 데이터 삭제, 기기 변경 시 파일 백업 없이는 복구되지 않는다.

## 5. 기술 구조

```mermaid
flowchart LR
  A[iPhone Safari / 홈 화면 PWA] --> B[버튼 녹음]
  B --> C[Safari SpeechRecognition 우선]
  C --> E[전사 텍스트]
  E --> F[기기 내 숫자·중량 파서]
  A --> G[직접 입력]
  F --> H[값 검증]
  G --> H
  H --> I[IndexedDB 세트 기록]
  I --> J[조회·수정·JSON 백업]
```

화면 자산은 Service Worker로 캐시해 연결이 없을 때도 열릴 수 있도록 설계한다. 음성에는 연결이 필요하다. **첫 구현은 Safari의 `SpeechRecognition`/`webkitSpeechRecognition`을 사용한다.** 브라우저가 기기 안에서 처리하는지 서버를 사용하는지 앱이 강제하거나 확인할 수 없으므로, 사용자에게 기기 밖 처리 가능성을 알린다. iPhone Safari·홈 화면 PWA에서 지원 또는 품질이 부족하면 사용자에게 허용받은 짧은 오디오 외부 전송 방식으로 바꾼다. 그 경우 HTTPS 서버, 비밀키 서버 보관, 인증·사용량 제한, 임시 오디오 폐기가 필요하다. 특정 STT 제공자·호스팅은 아직 선택하지 않았다.

기존 Python/FastAPI의 숫자 해석 규칙은 참고할 수 있지만, 파싱·기록은 PWA 내부에서 일관되게 처리한다. 기존 React Native 앱은 이번 배포 경로에 사용하지 않는다.

## 6. 구현 순서와 완료 기준

1. iPhone Safari와 홈 화면 PWA에서 HTTPS·마이크 권한·짧은 한국어 발화·브라우저 음성인식·연결 끊김을 시험한다.
2. 직접 기록, IndexedDB 저장·재실행·수정·조회, JSON 내보내기·복원을 완성한다.
3. 온라인 음성 API, 파서, 모호성 확인, 중복 저장 방지와 오류 복구를 연결한다.
4. 실제 헬스장 소음에서 운동 한 회를 기록하고 다음 날 기록·백업을 확인한다.

| 확인 항목 | 통과 조건 |
| --- | --- |
| 온라인 음성 | 연결된 iPhone에서 “8개”가 현재 종목·중량의 실제 8회로 저장됨 |
| 연결 없음 | 음성 불가 안내와 직접 입력이 보이고 실패한 음성 요청은 세트를 만들지 않음 |
| 기록 지속 | 앱 종료·재실행 후 세트가 남고 날짜·종목별로 조회·수정 가능 |
| 백업 | 내보낸 파일을 복원했을 때 세트 값·ID·취소 상태가 일치 |
| 오류 | 모호한 발화·권한 거부·중복 응답·중간 종료가 허위 완료를 만들지 않음 |
| 설치 | Safari와 홈 화면 PWA에서 각각 화면·마이크·저장 흐름 확인 |

인식률과 지연 목표는 실기기 측정 후 정한다. 문서 변경은 구현 또는 iPhone 검증 완료를 뜻하지 않는다.

## 7. 결정 기록

| 사용자 답변 | 현재 반영 |
| --- | --- |
| 지금은 따로 기록하지 않지만 저장 내역을 앱에서 확인해야 함 | 첫 기록·조회에 집중 |
| iPhone 17 / iOS 27, 마이크 버튼 허용 | iPhone Safari/PWA와 버튼 입력 중심 |
| 처음에는 본인 iPhone에서만 사용 | 계정·다중 사용자 제외 |
| Mac을 사용할 수 없고 앱스토어 등록·설치 비선호 | PWA 경로 채택 |
| 오프라인 음성 요구 철회 | 인터넷 필요 안내 + 직접 입력 복구 |
| 짧은 발화를 외부 음성인식 서버로 전송해도 됨 | 서버 STT 허용, 운동 기록은 iPhone에 보관 |

이전 문서의 오프라인 모델 다운로드, iOS 네이티브 음성 엔진, Xcode 빌드·설치 계획은 현재 MVP에서 제외한다.
