# iPhone 기본 받아쓰기 전환

## 적용 내용

- 앱에서 MediaRecorder, Web Speech, STT 서버 요청을 제거하고 표준 textarea를 사용합니다.
- 버튼 클릭 안에서 동기적으로 입력창을 열고 포커스를 주며, 키보드 마이크는 사용자가 누릅니다.
- 입력 확인 후 중량·횟수를 표시하고 별도 저장을 요구합니다. 수정 시 미리보기를 무효화합니다.
- 입력창은 main 렌더 영역 밖에 유지합니다. 네트워크/화면 전환 이벤트가 문장을 지우지 않습니다.
- 저장 중 버튼 잠금, inputId 중복 방지, 운동 컨텍스트 검증을 적용합니다.
- 기존 IndexedDB 스키마와 origin을 유지합니다. source=voice는 받아쓴 문장 경로에도 유지합니다.
- 앱 버전 20260926-8, 서비스 워커 voice-fitness-v14.
- 신규 배포 패키지는 정적 사이트만 포함합니다. 기존 STT 소스는 참고용으로 남겨둡니다.

## 검증

- 새 dictation 테스트를 먼저 실행해 모듈 부재로 실패하는 RED를 확인한 후 구현했습니다.
- node --test pwa/*.test.mjs: 35개 통과. 기존 STT 레거시 테스트도 포함됩니다.
- 브라우저 localhost:8878: 잘못된 문장 오류, 텍스트 수정 시 미리보기 무효화, 70kg 20회와 70kg 8회 연속 저장, 취소 후 추가 저장 없음, 새로고침 후 2세트 유지, 기록 탭 조회 확인.
- 이 검증에서는 문장을 타이핑했습니다. 실제 iPhone 받아쓰기 인식률·키보드 표시·마이크 조작은 사용자 기기 확인이 남아 있습니다.
- 로컬 검증 서버는 /api 요청을 오류로 처리하도록 구성했습니다. 테스트 중 API 요청 로그는 없었습니다.
- 패키지에서 dictation.mjs 포함 및 STT api 디렉터리 제외를 확인했습니다.

## 실제 NAS 반영

- 로컬 `.env`의 `NAS_SSH_USER`에 해당하는 SSH 계정으로 기존 사이트를 백업 후 정적 파일을 교체했습니다.
- 백업 위치: 로컬 `.env`의 `BACKUP_DICTATION_DIR` 참조.
- NAS localhost HTTP에서 새 버전을 확인했습니다.
- 공개 HTTPS에서 app.mjs, dictation.mjs, parser.mjs, index.html, styles.css, sw.js의 SHA-256이 로컬과 일치했습니다.
- 이번 live 변경은 site와 README만입니다. root 권한이 필요한 compose/nginx 재생성 및 기존 STT 컨테이너 종료는 실행하지 않았습니다. 기존 API 프록시는 아직 남아 있으며 새 앱에서는 호출하지 않습니다.
- deploy/nas의 새 compose/nginx는 향후 정리용 패키지에만 반영됐습니다. 정리 절차는 해당 README에 있습니다.

## 사용자 확인

Safari 새로고침 → 운동 이어하기 → 받아쓰기로 입력 → 키보드 마이크 → “70킬로 20회” → 받아쓰기 종료 → 입력 확인 → 기록 저장.
기존 버튼이 계속 보이면 앱을 완전히 닫았다가 다시 엽니다. Safari 데이터 삭제는 하지 않습니다.
