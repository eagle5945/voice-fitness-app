# 부위별 현황 · 20261002-35

- 부위: `BODY_PARTS` = 가슴, 등, 어깨, 하체, 팔, 코어(domain.mjs에 두어 백업 서버가 domain.mjs만으로 검사 가능)
- 데이터: 최상위 선택 필드 `exerciseParts` { 운동 이름(앞뒤 공백 제거, 60자 이하): 부위 }. 사용자가 고른 값만 저장. `setExercisePart(data, name, part | null)`, null이면 삭제. `emptyData`에 {} 추가, `validateBackup`은 일반 객체·키·값 검사(없거나 null이면 {}). 전체 기록 삭제 후에도 유지. 루틴·세트 형식은 그대로
- 추정(body-parts.mjs `guessPart`): 공백을 뺀 이름에 규칙을 순서대로 적용. 복합 이름 먼저(코어 레그레이즈 → 하체 레그컬·레그프레스·루마니안 → 백익스텐션 → 업라이트로우·리버스펙덱 → 가슴 → 팔 → 어깨 → 등 → 인클라인·덤벨프레스). 안 맞으면 null(분류 안 됨). 일반 데드리프트는 등
- 요약(`bodyPartSummary`): 최근 7일(현재 시각 기준 168시간) 세트·볼륨, 부위별 마지막 세트 시각. 종목은 주된 부위 하나에만 집계. 분류 안 된 세트는 따로 집계해 안내
- 회복(`recoveryStatus`, 앱 자체 기준): 48시간 미만 회복 중(warning·타이머), 168시간 미만 준비됨(success·체크), 그 이상 오래 쉼(neutral), 기록 없음은 배지 없이 글자로
- 화면: 기록 탭 ‘이번 주 리포트’ 다음 ‘부위별 현황’. 부위마다 마지막 세트(N시간 전/어제/N일 전), 세트 막대와 수, 회복 배지. ‘종목 분류’ 펼침에서 종목별 select(자동 · 추정값 / 6개 부위), 미분류 종목을 맨 위에. 변경 즉시 저장하며 펼침 상태와 select 포커스 유지
- 배포: 새 파일 `pwa/body-parts.mjs`를 sw.js FILES와 빌드 스크립트 SITE_FILES에 추가
- 백업 서버: 실행 중인 서버의 이전 domain.mjs로 `exerciseParts`가 든 백업을 검사해 필드가 그대로 남는 것을 확인. 서버는 재시작하지 않음

검증: domain 테스트 2개, body-parts 테스트 4개(운동 이름 43개 추정 포함) 추가, 전체 PWA 테스트 115개와 백업 서버 테스트 12개 통과. 브라우저에서 부위별 세트·회복 상태, 슈러그 미분류 안내와 어깨로 지정 후 반영, 펼침·포커스 유지, 375px에서 가로 스크롤 없음 확인.
